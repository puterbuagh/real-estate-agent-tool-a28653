# Real Estate Agent Tool
Stack: nextjs-supabase-vercel-stripe
Created: 2026-05-16

## Decisions
- Next.js 14.2.33 (App Router) with strict TypeScript and `@/*` path alias — pinned to published patched release clearing the security deprecation advisory (14.2.37 was non-existent and caused ETARGET install failures)
- `next.config.js` enforces type-safety and lint correctness at build time (no `typescript.ignoreBuildErrors`, no `eslint.ignoreDuringBuilds`) so Vercel deploys fail fast on regressions; configured `remotePatterns` for `maps.googleapis.com` to allow optimized Street View image loading via `next/image`
- Tailwind with AgentDesk design system: Space Grotesk display font, Inter body font, JetBrains Mono accents; navy sidebar, steel-blue primary, gradient mesh backgrounds, grain texture overlay utility
- Design tokens stored as HSL triplets in `globals.css` to pair with `hsl(var(--token))` Tailwind wrappers; elevated shadow tokens for lift states
- Print stylesheet in `globals.css` hides app chrome, forces light tokens, and exposes page-break utilities; adds `.no-print` and report-specific screen + print styles (A4 framing, page-break-inside avoid, display font for printed header/footer)
- `html, body { overflow-x: hidden }` in `globals.css` prevents global horizontal scroll; `AppShell` uses flexbox layout with fixed-width sidebar (256px) as flex child and flex-1 main content wrapper with `min-w-0` to prevent horizontal overflow; sidebar is static-positioned within the flex container (no sticky/fixed) so it renders once in document flow; mobile reverts to fixed slide-in overlay
- Sidebar component receives `mobileOpen` and `onClose` props in both mobile and desktop contexts for consistent API surface and future responsive behavior hooks; desktop ignores these props but accepts them to avoid prop-drilling conditionals in parent
- Supabase shared-schema client (browser + server) for cross-app data access; **all Supabase queries explicitly target shared schema via `.schema(SUPABASE_SCHEMA)` to prevent PGRST106 schema mismatch errors** — enforced across all API routes including property-overrides (POST/DELETE) and property-lookup (cache check/upsert) for consistent schema usage
- **Supabase Auth**: Email/password authentication with middleware route protection; public routes: `/login`, `/signup`, `/auth/callback`; all other routes require active session; server checks session via `createClient()` in middleware and redirects to `/login` on auth failure
- **Supabase client export pattern**: Browser client (`lib/supabase/client.ts`) exports `createSupabaseBrowserClient` as default export (named function declaration) for consistent import convention; server client (`lib/supabase/server.ts`) exports both `createClient` as default and `createServerClient` as named export alias for flexible import patterns; SignupForm and other client components import via `import createClient from '@/lib/supabase/client'` pattern
- **agent_profiles table**: PostgreSQL schema with `id` (uuid PK, references auth.users), `full_name`, `brokerage`, `email`, `phone`, `license_number`, `logo_url`, `location` (text, agent's primary market location for dynamic local stats labeling), `created_at`, `updated_at`; RLS policies: agents can read/update own row; auto-provision trigger on auth.users insert creates agent_profiles row with user email; **all queries and mutations use `full_name` column exclusively** — no legacy `name` or `avatar_url` columns exist in schema
- **property_valuations table**: Caches AgentDesk valuation results (agent_id, address, estimated_value, confidence_score, comp_count, valuation_date, created_at, updated_at) with RLS policies allowing agents to read/write own rows; unique constraint on (agent_id, address) prevents duplicate valuations per agent/property pair; **all queries use `.schema(SUPABASE_SCHEMA)` for explicit schema targeting**
- **property_overrides table**: Stores per-agent property field overrides (agent_id, address_hash (sha256 of normalized address), beds, baths, sqft, year_built, lot_size, property_sub_type, created_at, updated_at) with RLS policies allowing agents to read/write own rows; **composite unique constraint on (agent_id, address_hash) enforced at database level via migration 005** to prevent duplicate overrides; address_hash computed via SHA-256 of normalized address (trimmed + lowercased) for stable keying; enables agent-specific data corrections without mutating source ATTOM data; **API route configured with Node.js runtime** (`export const runtime = 'nodejs'`) to support crypto.createHash for SHA-256 hashing in Vercel's Node.js runtime environment; **comprehensive error logging at every step** (auth validation, JSON parsing, Supabase operations) with detailed error responses including Supabase error codes, hints, and full error objects for diagnostic troubleshooting; **schema verification confirms table existence and RLS policy presence before operations**; DELETE handler verifies row deletion and returns 404 status when override record not found (no rows affected); **all POST and DELETE operations use `.schema(SUPABASE_SCHEMA)` to target shared schema explicitly**
- **AgentBrandingContext canonical field**: `fullName` is the single source of truth for agent name across the entire branding system; hydrates from Supabase `agent_profiles.full_name` on mount (client-side fetch to `/api/profile`), saves to Supabase via POST to `/api/profile`, and falls back to localStorage for offline/guest mode; tracks `isConfigured` (fullName+brokerage populated) and `hasProfile` (all required fields saved) flags; **location field is synced bidirectionally between localStorage and Supabase**; **SignupForm writes to `full_name` column via `options.data.fullName` in signUp call** to match AgentBrandingContext's canonical field; **all components (SignupForm, ProfileForm, ReportPreview, ClientReportClient) consume agent name from AgentBrandingContext.fullName as single source of truth** with no hardcoded names or legacy field references; **context exports both default `AgentBrandingProvider` and named `AgentBrandingProvider` export** for flexible import patterns across the codebase; **comprehensive debug logging tracks fullName flow from ProfileForm save → API route → Supabase update → context hydration** to diagnose persistence issues; **persistToApi wrapped in try-catch with proper error handling** to prevent unhandled promise rejections
- Profile page (`/profile`) server-fetches agent data via Supabase server client, renders `ProfileForm` with Supabase sync; form saves to `/api/profile` route (includes location field) with toast feedback and auto-reloads context; **ProfileForm logs fullName value on save for debugging**; **API route logs incoming fullName and Supabase update parameters** to verify correct column mapping; **validation errors return structured response with issues array for detailed field-level diagnostics**; **AgentBrandingContext logs profile fetch response** to confirm full_name hydration from database
- Sidebar displays sign-out button with Supabase `signOut()` call (redirects to `/login`)
- FRED API as live source for mortgage rates (MORTGAGE30US + MORTGAGE15US), proxied via cached Next route with 12-week history per series
- **AgentDesk Valuation Engine**: Calculates property estimates by fetching comparable sales within 1-mile radius from ATTOM Sales History endpoint, filtering for similar bed/bath/sqft/year (±30% variance), applying recency weighting (exponential decay over 180 days), adjusting for size differential ($/sqft normalization), and computing weighted average; confidence score based on comp count (0.3 base + 0.15 per comp up to 5); requires 30yr mortgage rate from FRED for rate-adjusted calculations; results cached in `property_valuations` table with 7-day TTL; valuation data added as optional `agentDeskValuation` field to `ZillowProperty` interface; **comps retrieved via `fetchComparableSales()` from ATTOM sale/snapshot endpoint with 1-mile radius filter before valuation calculation** to ensure confidence scores reflect actual comp availability; **client-safe `calculateAgentDeskEstimate` exported from lib/valuation.ts** for live recalculation during property override editing (accepts ValuationInputs: beds, baths, sqft, yearBuilt, address, comps, mortgageRate30yr); **cache upsert uses `.schema(SUPABASE_SCHEMA)` for schema-targeted writes**
- **Property override workflow**: PropertyCard exposes inline edit mode for beds/baths/sqft/yearBuilt/lotSize/propertySubType fields; changes trigger live valuation recalculation via client-safe `calculateAgentDeskEstimate` with before/after estimate comparison; save writes to `/api/property-overrides` (POST with auth-gated Supabase upsert using `.schema(SUPABASE_SCHEMA)`); reset clears overrides via DELETE to `/api/property-overrides` (with `.schema(SUPABASE_SCHEMA)`) with 404 status returned when no override exists; visual dot indicators mark edited fields; override values loaded from Supabase in `/api/property-lookup` via address hash lookup (with `.schema(SUPABASE_SCHEMA)`) and merged into property response before valuation calculation; overrides affect only AgentDesk estimate (ATTOM source data unchanged); **PropertyCard correctly initializes editValues from property.overrides on mount via useEffect to prevent edit-mode initialization bugs**; **editValues typed with empty strings for cleared inputs (not null) to maintain controlled input state**; **crypto.createHash usage isolated to Node.js runtime API routes** (removed from client components); **PropertyCard uses isClient flag to gate all edit mode UI state and prevent hydration mismatches**; **property-overrides route exports `runtime = 'nodejs'` to enable SHA-256 hashing in Vercel's Node.js runtime**; **PropertyCard handleSave parses API error responses with comprehensive fallback chain** (API error message → PostgreSQL error details → HTTP status text → generic fallback) and displays user-facing error toasts via sonner with actual diagnostic information from failed override operations
- All third-party API keys are server-only or public env vars — `FRED_API_KEY` and `ATTOM_API_KEY` are server-only (never `NEXT_PUBLIC_*`); `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is client-accessible for Google Maps/Places integration (read directly by client code, not stored in agent profiles)
- Google Maps/Places integration uses `@googlemaps/js-api-loader` (client-side script loader) + `@types/google.maps`; Places Autocomplete enabled in Property Comparator address inputs by reading `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` directly from environment (no API route, no profile storage); graceful degradation to manual address entry when key missing or API fails; comprehensive debug logging in `lib/google-places.ts` (tagged-result API for loader errors) and `AddressInputs` component (logs autocomplete service init, input attachment, place selection with lat/lng extraction) for end-to-end troubleshooting
- **Google Street View integration**: PropertyCard displays optimized Street View photos via Google Static Street View API using lat/lng coordinates; `next/image` component fetches 600x400px Street View imagery with `fov=90&pitch=0` for standard perspective; `next.config.js` includes `maps.googleapis.com` in `remotePatterns` for image optimization; graceful fallback to house icon placeholder when Street View returns no coverage (HTTP 200 with gray "no imagery" response); Street View images hidden in print mode via `no-print` class
- **AddressInputs Google Places integration**: Uses legacy `google.maps.places.Autocomplete` API exclusively; listens for `place_changed` event, extracts `place.geometry.location` (lat/lng) and `place.formatted_address`, writes formatted_address to the native input value, stores lat/lng in hidden state, and propagates via `onChange({ address: string, lat: number, lng: number })` to parent state (lat/lng params optional for backward compat with manual entry); property-comparator page wires `onPlaceSelected` callback to capture lat/lng from Places selections, writes coordinates to address state, and passes to `/api/property-lookup` for coordinate-based ATTOM lookup
- `/api/mortgage-rate` returns `{ rate30yr: RateSeries, rate15yr: RateSeries }` with current value, week-over-week delta, and history points; `StatsGrid` is backward-compatible with this shape (legacy-shape fallback typing includes `currentDate`)
- `/api/mortgage-rate` is auth-gated via Supabase session (401 on missing session), per-user sliding-window in-memory rate limit of 30 req/min (429 with `Retry-After` header), and edge-cached with `Cache-Control: s-maxage=3600, stale-while-revalidate=86400` + `Vary: Cookie` to prevent FRED quota abuse while preserving per-user auth boundaries
- Market Stats page server-fetches the 30yr FRED rate (using server-only `FRED_API_KEY`) and passes it as a prefill prop to `MortgageCalculator` and `AffordabilityCheck` for instant-loaded live-rate defaults
- **ATTOM API integration**: ATTOM Data Solutions REST API with base URL extracted to `ATTOM_BASE_URL` constant (`https://api.gateway.attomdata.com/propertyapi/v1.0.0`); uses Property Detail (`/property/detail`) + AVM (`/avm/detail`) + Sales History (`/saleshistory/detail`) + **Sale/Snapshot (`/sale/snapshot`) for comparable sales retrieval** endpoints for comprehensive property data; **Property Detail provides address/beds/baths/sqft/lotSize/yearBuilt/propertySubType, AVM provides estimatedValue, Sales History provides lastSalePrice/lastSaleDate, Sale/Snapshot provides comps within 1-mile radius**; accepts lat/lng from Google Places Autocomplete; coordinate validation rejects invalid/missing lat/lng with `400 { ok:false, error:'Invalid coordinates', errorType:'not_found', property:null }` before API call (errorType aligned with UI state for refine-address guidance); implements multi-endpoint parallel fetch with 30s timeout + 3-attempt exponential backoff (2s→4s→8s with jitter); coordinate validation with US bounds check (24.396308°N–49.384358°N, -125.0°W–-66.93457°W); proxied through `/api/property-lookup` with consistent `{ok, data|error, errorType?}` envelope; comprehensive diagnostic logging with timestamps for coordinate validation, ATTOM request/response, and error classification; **full raw ATTOM response logging for property/avm/sales/snapshot endpoints** to diagnose missing data issues; **valuation engine integration fetches comps from ATTOM Sale/Snapshot via `fetchComparableSales()`, calculates weighted estimate with confidence score, caches results in property_valuations table**; **all Supabase queries use `.schema(SUPABASE_SCHEMA)` for explicit schema targeting**
- **Toast notifications via sonner**: Added `sonner` package for user-facing error and success notifications; `<Toaster />` component mounted in RootLayout for app-wide toast support; ProfileForm and PropertyCard use sonner for save/reset feedback

## Components
- AppShell: Flexbox layout with static 256px sidebar + flex-1 main content wrapper (min-w-0 prevents horizontal overflow); mobile switches to fixed overlay sidebar
- Sidebar: Static-positioned navigation panel with AgentDesk logo, nav links, and sign-out button; accepts mobileOpen/onClose props for responsive behavior hooks
- StatsGrid: Market stats dashboard with mortgage rates (30yr/15yr from FRED), inventory count, median sale price, days on market; renders FRED rate history sparklines with week-over-week deltas
- PropertyCard: Editable property detail card with inline edit mode for beds/baths/sqft/yearBuilt/lotSize/propertySubType; live valuation recalculation on field changes; visual dot indicators for edited fields; save/reset controls for Supabase override persistence (via `.schema(SUPABASE_SCHEMA)`-targeted API routes); Google Street View image integration with optimized loading via next/image; **isClient flag gates all edit mode UI to prevent hydration mismatches**; **handleSave parses API error responses with multi-layer fallback** (error.error → error.details → statusText → generic) and displays user-facing toast notifications via sonner with actual diagnostic messages from /api/property-overrides failures
- AddressInputs: Google Places Autocomplete-enabled address input with lat/lng extraction; listens for place_changed event, stores coordinates in hidden state, propagates formatted_address + lat/lng to parent via onChange callback
- MortgageCalculator: Interactive mortgage payment calculator with live-rate prefill from FRED API
- AffordabilityCheck: Income-based home affordability calculator with live-rate prefill
- ProfileForm: Agent profile editor synced to Supabase agent_profiles table; saves fullName/brokerage/email/phone/licenseNumber/location via POST to /api/profile with sonner toast feedback; **logs fullName value on save** to verify correct data submission
- AgentBrandingProvider: React context wrapping app root; hydrates agent branding (fullName/brokerage/location) from Supabase on mount, syncs to localStorage, exposes isConfigured/hasProfile flags; **logs profile fetch response** to verify full_name hydration from database; **persistToApi wrapped in try-catch for robust error handling**
