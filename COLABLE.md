# Real Estate Agent Tool
Stack: nextjs-supabase-vercel-stripe
Created: 2026-05-16

## Decisions
- Next.js 14.2.33 (App Router) with strict TypeScript and `@/*` path alias — pinned to published patched release clearing the security deprecation advisory (14.2.37 was non-existent and caused ETARGET install failures)
- `next.config.js` enforces type-safety and lint correctness at build time (typescript.ignoreBuildErrors and eslint.ignoreDuringBuilds both false) so Vercel deploys fail fast on regressions; configured `remotePatterns` for `maps.googleapis.com` to allow optimized Street View image loading via `next/image`; **Content-Security-Policy headers block unsafe-inline scripts and whitelist only approved external domains** (maps.googleapis.com for Street View, api.fred.stlouisfed.org for mortgage rates, api.gateway.attomdata.com for property data, explicit Supabase project URL via NEXT_PUBLIC_SUPABASE_URL for connect-src, *.supabase.co for auth/storage); script-src excludes 'wasm-unsafe-eval' for tighter security posture; **additional security headers** include X-Frame-Options DENY, X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin, Permissions-Policy camera=(), microphone=(), geolocation=()
- Tailwind with AgentDesk design system: Space Grotesk display font, Inter body font, JetBrains Mono accents; navy sidebar, steel-blue primary, gradient mesh backgrounds, grain texture overlay utility
- Design tokens stored as HSL triplets in `globals.css` to pair with `hsl(var(--token))` Tailwind wrappers; elevated shadow tokens for lift states
- Print stylesheet in `globals.css` hides app chrome, forces light tokens, and exposes page-break utilities; adds `.no-print` and report-specific screen + print styles (A4 framing, page-break-inside avoid, display font for printed header/footer)
- `html, body { overflow-x: hidden }` in `globals.css` prevents global horizontal scroll; `AppShell` uses flexbox layout with fixed-width sidebar (256px) as flex child and flex-1 main content wrapper with `min-w-0` to prevent horizontal overflow; sidebar is static-positioned within the flex container (no sticky/fixed) so it renders once in document flow; **mobile uses fixed overlay sidebar toggled via hamburger menu in TopBar** (lg:hidden, triggers onMenuClick prop passed to TopBar and wired to hamburger button click handler in AppShell state management)
- Sidebar component receives `mobileOpen` and `onClose` props in both mobile and desktop contexts for consistent API surface and future responsive behavior hooks; desktop ignores these props but accepts them to avoid prop-drilling conditionals in parent; **sign-out handler uses router.replace('/login') to prevent back-button access to authenticated routes after logout**, properly awaits signOut() completion before redirecting, displays toast error notifications on failed sign-out, and resets loading state in all error paths to prevent permanent button disabled state; **uses named import for Supabase browser client**; **displays demo mode badge when authenticated as demo@agentdesk.app**
- **Supabase client configuration sets schema at factory level**: `createSupabaseBrowserClient` and `createClient`/`createServerClient` include `db: { schema: SUPABASE_SCHEMA }` in client config, eliminating need for per-query `.schema()` calls; `SUPABASE_SCHEMA` constant exported from both client.ts and server.ts reads from `NEXT_PUBLIC_SUPABASE_SCHEMA` (set to `agentdesk`)
- **Supabase Auth**: Email/password authentication with middleware route protection; public routes: `/login`, `/signup`, `/auth/callback`, `/demo`; all other routes require active session; server checks session via `createClient()` in middleware and redirects to `/login` on auth failure; **all auth forms (LoginForm, SignupForm, DemoLoginForm) redirect to dashboard (/) after successful sign-in** instead of /profile to streamline onboarding; **sign-out uses router.replace to prevent back-button access**, awaits signOut() completion, displays toast error notifications on failures, and ensures loading state reset in error paths to prevent UI lockup; **demo user flow** allows password-protected one-click sign-in as demo@agentdesk.app with pre-seeded sample data via /demo page; **/api/demo-auth route validates DEMO_PASSWORD for /demo page access control only** — does not perform Supabase authentication (client-side DemoLoginForm handles signInWithPassword after password check); **demo@agentdesk.app auth.users account must be manually created in Supabase Dashboard** with chosen password before migration 006 seeds profile/pipeline data; **DEMO_PASSWORD env var is for /demo page access gating, separate from Supabase auth credential**; migration 006 includes updated instructions documenting manual auth.users creation requirement
- **Supabase client export pattern**: Browser client (`lib/supabase/client.ts`) exports **both named export `createSupabaseBrowserClient` and default export of the same function** to support flexible import patterns across codebase without runtime errors; server client (`lib/supabase/server.ts`) exports both `createClient` as default and `createServerClient` as named export alias plus `SUPABASE_SCHEMA` constant; **all client-side components use named import syntax** (`import { createSupabaseBrowserClient } from '@/lib/supabase/client'`) for consistent browser client instantiation (Sidebar, AgentBrandingContext, PipelineContext, DemoLoginForm, LoginForm, SignupForm); **DemoLoginForm validates NEXT_PUBLIC_SUPABASE_URL env var before sign-in attempt and displays error toast with setup guidance when missing**
- **agent_profiles table**: PostgreSQL schema with `id` (uuid PK, references auth.users), `full_name`, `brokerage`, `email`, `phone`, `license_number`, `logo_url`, `location` (text, agent's primary market location for dynamic local stats labeling), `created_at`, `updated_at`; RLS policies: agents can read/update own row; auto-provision trigger on auth.users insert creates agent_profiles row with user email; **all queries and mutations use `full_name` column exclusively**; **demo user (demo@agentdesk.app) pre-seeded with sample profile data** via migration 006 after manual auth.users creation in Dashboard
- **property_valuations table**: Caches AgentDesk valuation results (agent_id, address, estimated_value, confidence_score, comp_count, valuation_date, created_at, updated_at) with RLS policies allowing agents to read/write own rows; unique constraint on (agent_id, address) prevents duplicate valuations per agent/property pair
- **property_overrides table**: Stores per-agent property field overrides (agent_id, address_hash (sha256 of normalized address), beds, baths, sqft, year_built, lot_size, property_sub_type, created_at, updated_at) with RLS policies allowing agents to read/write own rows; **composite unique constraint on (agent_id, address_hash) enforced at database level via migration 005**; address_hash computed via SHA-256 of normalized address (trimmed + lowercased); **API route configured with Node.js runtime** to support crypto.createHash for SHA-256 hashing
- **pipeline_properties table**: Stores agent's sales pipeline (agent_id, address, property_data jsonb, stage text, notes text, created_at, updated_at) with RLS policies allowing agents to read/write own rows; supports CRUD operations for pipeline management; **demo user pre-seeded with sample pipeline properties** via migration 006 after manual auth.users creation in Dashboard
- **AgentBrandingContext canonical field**: `fullName` is the single source of truth for agent name across the entire branding system; hydrates from Supabase `agent_profiles.full_name` on mount (client-side fetch to `/api/profile`), saves to Supabase via POST to `/api/profile`, and falls back to localStorage for offline/guest mode; tracks `isConfigured` (fullName+brokerage populated) and `hasProfile` (all required fields saved) flags; **location field is synced bidirectionally between localStorage and Supabase**; **SignupForm writes to `full_name` column via `options.data.fullName` in signUp call**; **context uses named import for Supabase browser client**; **persistToApi wrapped in try-catch for robust error handling**; **exports AgentBrandingProvider as default and useAgentBranding as named export for consistent import patterns**
- Profile page (`/profile`) server-fetches agent data via Supabase server client, renders `ProfileForm` with Supabase sync; form saves to `/api/profile` route (includes location field) with toast feedback and auto-reloads context
- FRED API as live source for mortgage rates (MORTGAGE30US + MORTGAGE15US), proxied via cached Next route with 12-week history per series
- **AgentDesk Valuation Engine**: Calculates property estimates by fetching comparable sales within 1-mile radius from ATTOM Sales History endpoint, filtering for similar bed/bath/sqft/year (±30% variance), applying recency weighting (exponential decay over 180 days), adjusting for size differential ($/sqft normalization), and computing weighted average; confidence score based on comp count (0.3 base + 0.15 per comp up to 5); requires 30yr mortgage rate from FRED for rate-adjusted calculations; results cached in `property_valuations` table with 7-day TTL; **comps retrieved via `fetchComparableSales()` from ATTOM sale/snapshot endpoint with 1-mile radius filter before valuation calculation**; **client-safe `calculateAgentDeskEstimate` exported from lib/valuation.ts** for live recalculation during property override editing
- **Property override workflow**: PropertyCard exposes inline edit mode for beds/baths/sqft/yearBuilt/lotSize/propertySubType fields; changes trigger live valuation recalculation via client-safe `calculateAgentDeskEstimate` with before/after estimate comparison; save writes to `/api/property-overrides` (POST with auth-gated Supabase upsert); reset clears overrides via DELETE to `/api/property-overrides` with 404 status returned when no override exists; visual dot indicators mark edited fields; override values loaded from Supabase in `/api/property-lookup` via address hash lookup and merged into property response before valuation calculation; **PropertyCard correctly initializes editValues from property.overrides on mount via useEffect**; **crypto.createHash usage isolated to Node.js runtime API routes**; **PropertyCard uses isClient flag to gate all edit mode UI state and prevent hydration mismatches**; **handleSave and handleReset parse API error responses with comprehensive fallback chain and network-error detection** displaying user-facing error toasts via sonner with distinct messaging for connection failures vs API errors
- All third-party API keys are server-only or public env vars — `FRED_API_KEY` and `ATTOM_API_KEY` are server-only (never `NEXT_PUBLIC_*`); `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is client-accessible for Google Maps/Places integration; **`DEMO_PASSWORD` is server-only env var validated via /api/demo-auth route for /demo page access control** (does not perform Supabase authentication); **demo@agentdesk.app password set during manual auth.users creation in Supabase Dashboard is separate credential used by DemoLoginForm signInWithPassword**; .env.example includes critical setup instructions documenting DEMO_PASSWORD is for page access only
- Google Maps/Places integration uses `@googlemaps/js-api-loader` (client-side script loader) + `@types/google.maps`; Places Autocomplete enabled in Property Comparator address inputs by reading `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` directly from environment; graceful degradation to manual address entry when key missing or API fails; **lib/google-places.ts utility has no 'use client' directive** as it exports server-compatible functions only
- **Google Street View integration**: PropertyCard displays optimized Street View photos via Google Static Street View API using lat/lng coordinates; `next/image` component fetches 600x400px Street View imagery; `next.config.js` includes `maps.googleapis.com` in `remotePatterns`; graceful fallback to house icon placeholder when Street View returns no coverage; Street View images hidden in print mode via `no-print` class; **exclusive skeleton rendering pattern**: while imageLoading=true, ONLY Skeleton component renders in DOM; hidden sr-only img preloader fires onLoad to flip state, then real next/image mounts after load completes
- **AddressInputs Google Places integration**: Uses legacy `google.maps.places.Autocomplete` API exclusively; listens for `place_changed` event, extracts `place.geometry.location` (lat/lng) and `place.formatted_address`, writes formatted_address to the native input value, stores lat/lng in hidden state, and propagates via `onChange({ address: string, lat: number, lng: number })` to parent state
- `/api/mortgage-rate` returns `{ rate30yr: RateSeries, rate15yr: RateSeries }` with current value, week-over-week delta, and history points; auth-gated via Supabase session (401 on missing session), per-user sliding-window in-memory rate limit of 30 req/min (429 with `Retry-After` header), and edge-cached with `Cache-Control: s-maxage=3600, stale-while-revalidate=86400` + `Vary: Cookie`
- Market Stats page server-fetches the 30yr FRED rate (using server-only `FRED_API_KEY`) and passes it as a prefill prop to `MortgageCalculator` and `AffordabilityCheck` for instant-loaded live-rate defaults
- **ATTOM API integration**: ATTOM Data Solutions REST API with base URL extracted to `ATTOM_BASE_URL` constant; uses Property Detail + AVM + Sales History + **Sale/Snapshot for comparable sales retrieval** endpoints; accepts lat/lng from Google Places Autocomplete; coordinate validation rejects invalid/missing lat/lng with 400 error before API call; implements multi-endpoint parallel fetch with 30s timeout + 3-attempt exponential backoff; coordinate validation with US bounds check; proxied through `/api/property-lookup` with consistent `{ok, data|error, errorType?}` envelope; **valuation engine integration fetches comps from ATTOM Sale/Snapshot via `fetchComparableSales()`, calculates weighted estimate with confidence score, caches results in property_valuations table**
- **Toast notifications via sonner**: Added `sonner` package for user-facing error and success notifications; `<Toaster />` component mounted in RootLayout for app-wide toast support; all mutation operations (PropertyCard save/reset, ProfileForm save, PipelineCard save/delete, AddPropertyForm submit, Sidebar sign-out) display toast feedback for success/error states; **network error detection distinguishes connection failures from API errors with distinct toast messages**
- **Component export pattern**: All components export both a default export and a matching named export for consistent import patterns across the codebase; context providers (AgentBrandingContext, PipelineContext) export provider as default and hook as named export
- **Mobile responsive tables**: All comparison tables (ComparisonTable, RecentComparisons) wrapped in `w-full max-w-full overflow-x-auto` containers with `min-w-[640px]` constraint on table element to enable horizontal scroll on mobile (<640px) while preserving full table layout on desktop; table headers use `whitespace-nowrap` to prevent text wrapping; Property Comparator page layout uses clean constraint-based responsive grid without redundant scroll containers; parent wrappers use `w-full max-w-full` to prevent overflow propagation while child tables handle scroll with `overflow-x-auto min-w-[640px]`
- **Loading states**: All async operations show explicit loading indicators with consistent patterns — **ProfileForm save button renders explicit Loader2 spinner with 'Saving…' text during submit, disables all form fields**, no longer relying solely on Button's loading prop; **PropertyCard Street View renders ONLY Skeleton component in DOM while imageLoading=true with hidden sr-only preloader to detect load completion**; **Property Comparator Compare button shows spinner with integrated elapsed time display** in loading UI section; **AddPropertyForm submit button shows spinner during pipeline add** with network error detection in toast messaging; **PipelineCard save/delete buttons show spinners during Supabase mutations**; **StatsGrid shows skeleton placeholders matching actual StatCard component structure** with three skeleton cards for mortgage rate data during FRED fetch; **Sidebar sign-out button shows spinner during signOut() operation and resets to idle state on errors**
- **Demo user flow**: Password-protected demo authentication route at `/demo` with server-side DEMO_PASSWORD validation via `/api/demo-auth` for page access control only (returns 200 on match, 401 on mismatch); **client-side DemoLoginForm performs actual Supabase signInWithPassword after password check**; **DemoLoginForm validates NEXT_PUBLIC_SUPABASE_URL env var before sign-in attempt and displays error toast with setup guidance when missing**; **demo@agentdesk.app auth.users account must be manually created in Supabase Dashboard** with chosen password before running migration 006; migration 006 seeds demo user with sample agent profile (Jane Smith from Acme Realty) and pipeline properties (3 sample homes across Prospect/Active/Under Contract stages) and includes updated instructions documenting manual auth.users creation requirement; demo mode badge displayed in Sidebar when authenticated as demo user; **redirects to dashboard (/) after successful sign-in**; `/demo` whitelisted in middleware as public auth route; .env.example includes critical setup instructions documenting DEMO_PASSWORD is for /demo page access only and separate from Supabase auth credential
- **Production readiness assessment completed**: 22 prioritized recommendations across critical blockers (mobile UX, loading states, Supabase quota risks, Places API security), high-priority items (error boundaries, rate limiting, onboarding, offline support), medium-priority fixes (accessibility, SEO, analytics, testing), and low-priority polish (keyboard shortcuts, theming, print optimization); includes security audit (API key rotation, CSP, dependency scanning), performance checklist (Edge Runtime, image optimization, bundle analysis), tech debt inventory (type safety, API consolidation, client-server separation), and 4-week post-launch roadmap with phased rollout plan

## Components
- AppShell: Flexbox layout with static 256px sidebar + flex-1 main content wrapper (min-w-0 prevents horizontal overflow); **mobile manages mobileMenuOpen state and passes setMobileMenuOpen handler to TopBar via onMenuClick prop for hamburger menu toggle**; sidebar overlay controlled via mobileMenuOpen state and onClose callback
- TopBar: Mobile-only navigation bar with hamburger menu button (lg:hidden) wired to onMenuClick prop; **click handler triggers parent AppShell's setMobileMenuOpen state update to open/close sidebar overlay**
- Sidebar: Static-positioned navigation panel with AgentDesk logo, nav links, and sign-out button; **sign-out handler uses router.replace('/login') to prevent back-button access to authenticated routes after logout**, properly awaits signOut() completion before redirecting, displays toast error notifications on failures, and resets loading state in all error paths to prevent permanent button disabled state; **uses named import for Supabase browser client**; accepts mobileOpen/onClose props for responsive behavior hooks; **displays demo mode badge when authenticated as demo@agentdesk.app**
- StatsGrid: Market stats dashboard with mortgage rates (30yr/15yr from FRED), inventory count, median sale price, days on market; renders FRED rate history sparklines with week-over-week deltas; **shows skeleton placeholders matching actual StatCard component structure** with three skeleton cards during mortgage rate fetch; **exports single default export**
- PropertyCard: Editable property detail card with inline edit mode for beds/baths/sqft/yearBuilt/lotSize/propertySubType; live valuation recalculation on field changes; visual dot indicators for edited fields; **save/reset buttons show loading spinners during Supabase operations with network-error detection in toast messaging**; Google Street View image integration with **exclusive skeleton rendering pattern — ONLY Skeleton in DOM while imageLoading=true, hidden sr-only preloader triggers load completion, then next/image mounts**; **isClient flag gates all edit mode UI to prevent hydration mismatches**; **handleSave and handleReset parse API error responses with multi-layer fallback and network-error differentiation**; **exports both default and named PropertyCard export**
- PropertySkeletonCard: Enhanced skeleton placeholder matching full PropertyCard layout with Street View placeholder area, address skeleton, price/beds/baths skeletons, and property details section; **shown during initial property load in Property Comparator**; **exports both default and named export**
- PropertyErrorCard: Error state card for property lookup failures; **exports both default and named export**
- AddressInputs: Google Places Autocomplete-enabled address input with lat/lng extraction; listens for place_changed event, stores coordinates in hidden state, propagates formatted_address + lat/lng to parent via onChange callback; **exports both default and named export**
- MortgageCalculator: Interactive mortgage payment calculator with live-rate prefill from FRED API
- AffordabilityCheck: Income-based home affordability calculator with live-rate prefill
- ProfileForm: Agent profile editor synced to Supabase agent_profiles table; **save button renders explicit Loader2 spinner with 'Saving…' text during submit, disables all form fields**, no longer relying solely on Button's loading prop; saves fullName/brokerage/email/phone/licenseNumber/location via POST to /api/profile with network-error differentiated toast feedback
- AgentBrandingProvider: React context wrapping app root; hydrates agent branding (fullName/brokerage/location) from Supabase on mount via named import for Supabase browser client, syncs to localStorage, exposes isConfigured/hasProfile flags; **persistToApi wrapped in try-catch for robust error handling**; **exports provider as default and useAgentBranding hook as named export**
- PipelineContext: Client pipeline state management with Supabase sync to pipeline_properties table via named import for Supabase browser client; CRUD operations for pipeline items (add/remove/update stage/update notes); loads user's pipeline from Supabase on mount after auth; **exports PipelineProvider as default and usePipeline hook as named export**
- QuickAddToPipeline: Quick-add button for adding properties to pipeline from comparator view; **exports both default and named export**
- AddPropertyForm: Form for adding new properties to pipeline with address/stage/notes fields; **submit button shows loading spinner during pipeline add** with network error detection distinguishing connection failures from API errors in toast messaging; displays toast notifications for success/error states; **exports both default and named export**
- KanbanBoard: Kanban-style pipeline board with drag-and-drop stage management; **exports both default and named export**
- PipelineCard: Individual pipeline property card with stage/notes editing; **save/delete buttons show loading spinners during Supabase mutations**; displays toast notifications for operation feedback; **exports both default and named export**
- AgentBrandingForm: Client report branding editor using AgentBranding type fields (fullName, location, logoUrl, avatarUrl) matching context schema
- ComparisonSelector: Property comparison selector for client reports; **exports single default export**
- ReportPreview: Client report preview with agent branding integration via useAgentBranding hook; **exports single default export**
- ClientReportClient: Client-side report orchestrator passing branding shape compatible with ReportPreview; **Property Comparator Compare button shows spinner with integrated elapsed time display** in loading UI section
- ComparisonTable: Property comparison table with **mobile-responsive `w-full max-w-full overflow-x-auto` wrapper on parent section and `min-w-[640px]` constraint on table** for horizontal scroll on <640px screens; whitespace-nowrap on headers to prevent text wrapping
- RecentComparisons: Dashboard widget displaying recent property comparisons with **mobile-responsive `w-full max-w-full overflow-x-auto` wrapper at outermost container level and `min-w-[640px]` constraint on table element** for horizontal scroll on <640px screens; whitespace-nowrap on headers to prevent text wrapping
- DemoLoginForm: Password-protected demo authentication component for /demo page; **validates DEMO_PASSWORD server-side via POST to /api/demo-auth for page access control only** (does not perform Supabase auth); accepts `isUnlocked` prop to conditionally render one-click sign-in button after password validation; **validates NEXT_PUBLIC_SUPABASE_URL env var before sign-in attempt and displays error toast with setup guidance when missing**; **uses named import for Supabase browser client**; **client-side signInWithPassword uses password set during manual demo@agentdesk.app auth.users creation in Supabase Dashboard** (separate from DEMO_PASSWORD env var); **redirects to dashboard (/) after successful sign-in** with toast feedback and loading states
- LoginForm: Email/password login form with client-side validation and error handling; **uses named import for Supabase browser client**; **redirects to dashboard (/) on successful authentication**
- SignupForm: Email/password signup form with agent profile creation; **writes to `full_name` column via `options.data.fullName` in signUp call**; **uses named import for Supabase browser client**; **redirects to dashboard (/) after successful signup**
