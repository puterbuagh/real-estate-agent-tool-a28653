# Real Estate Agent Tool
Stack: nextjs-supabase-vercel-stripe
Created: 2026-05-16

## Decisions
- Next.js 14.2.33 (App Router) with strict TypeScript and `@/*` path alias — pinned to published patched release clearing the security deprecation advisory (14.2.37 was non-existent and caused ETARGET install failures)
- `next.config.js` enforces type-safety and lint correctness at build time (no `typescript.ignoreBuildErrors`, no `eslint.ignoreDuringBuilds`) so Vercel deploys fail fast on regressions
- Tailwind with AgentDesk design system: Space Grotesk display font, Inter body font, JetBrains Mono accents; navy sidebar, steel-blue primary, gradient mesh backgrounds, grain texture overlay utility
- Design tokens stored as HSL triplets in `globals.css` to pair with `hsl(var(--token))` Tailwind wrappers; elevated shadow tokens for lift states
- Print stylesheet in `globals.css` hides app chrome, forces light tokens, and exposes page-break utilities; adds `.no-print` and report-specific screen + print styles (A4 framing, page-break-inside avoid, display font for printed header/footer)
- `html, body { overflow-x: hidden }` in `globals.css` prevents global horizontal scroll; `AppShell` uses flexbox layout with fixed-width sidebar (256px) as flex child and flex-1 main content wrapper with `min-w-0` to prevent horizontal overflow; sidebar is static-positioned within the flex container (no sticky/fixed) so it renders once in document flow; mobile reverts to fixed slide-in overlay
- Sidebar component receives `mobileOpen` and `onClose` props in both mobile and desktop contexts for consistent API surface and future responsive behavior hooks; desktop ignores these props but accepts them to avoid prop-drilling conditionals in parent
- Supabase shared-schema client (browser + server) for cross-app data access
- **Supabase Auth**: Email/password authentication with middleware route protection; public routes: `/login`, `/signup`, `/auth/callback`; all other routes require active session; server checks session via `createClient()` in middleware and redirects to `/login` on auth failure
- **Supabase client export pattern**: Browser client (`lib/supabase/client.ts`) exports `createSupabaseBrowserClient` as default export (named function declaration) for consistent import convention; SignupForm and other client components import via `import createClient from '@/lib/supabase/client'` pattern
- **agent_profiles table**: PostgreSQL schema with `id` (uuid PK, references auth.users), `full_name`, `brokerage`, `email`, `phone`, `license_number`, `logo_url`, `location` (text, agent's primary market location for dynamic local stats labeling), `created_at`, `updated_at`; RLS policies: agents can read/update own row; auto-provision trigger on auth.users insert creates agent_profiles row with user email
- `AgentBrandingContext` hydrates from Supabase `agent_profiles` on mount (client-side fetch to `/api/profile`), saves to Supabase on `saveBranding()` (POST to `/api/profile`), and falls back to localStorage for offline/guest mode; tracks `isConfigured` (name+brokerage populated) and `hasProfile` (all required fields saved) flags; **location field is synced bidirectionally between localStorage and Supabase**
- Profile page (`/profile`) server-fetches agent data via Supabase server client, renders `ProfileForm` with Supabase sync; form saves to `/api/profile` route (includes location field) with toast feedback and auto-reloads context
- Sidebar displays sign-out button with Supabase `signOut()` call (redirects to `/login`)
- FRED API as live source for mortgage rates (MORTGAGE30US + MORTGAGE15US), proxied via cached Next route with 12-week history per series
- All third-party API keys are server-only or public env vars — `FRED_API_KEY` and `RAPIDAPI_KEY` are server-only (never `NEXT_PUBLIC_*`); `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is client-accessible for Google Maps/Places integration (read directly by client code, not stored in agent profiles)
- Google Maps/Places integration uses `@googlemaps/js-api-loader` (client-side script loader) + `@types/google.maps`; Places Autocomplete enabled in Property Comparator address inputs by reading `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` directly from environment (no API route, no profile storage); graceful degradation to manual address entry when key missing or API fails; comprehensive debug logging in `lib/google-places.ts` (tagged-result API for loader errors) and `AddressInputs` component (logs autocomplete service init, input attachment, place selection with lat/lng extraction) for end-to-end troubleshooting
- **AddressInputs Google Places integration**: Uses legacy `google.maps.places.Autocomplete` API exclusively; listens for `place_changed` event, extracts `place.geometry.location` (lat/lng) and `place.formatted_address`, writes formatted_address to the native input value, stores lat/lng in hidden state, and propagates via `onChange({ address: formatted_address, lat, lng })` to parent state (lat/lng params optional for backward compat with manual entry); property-comparator page wires `onPlaceSelected` callback to capture lat/lng from Places selections, writes coordinates to address state, and passes to `/api/property-lookup` for coordinate-based Zillow lookup
- `/api/mortgage-rate` returns `{ rate30yr: RateSeries, rate15yr: RateSeries }` with current value, week-over-week delta, and history points; `StatsGrid` is backward-compatible with this shape (legacy-shape fallback typing includes `currentDate`)
- `/api/mortgage-rate` is auth-gated via Supabase session (401 on missing session), per-user sliding-window in-memory rate limit of 30 req/min (429 with `Retry-After` header), and edge-cached with `Cache-Control: s-maxage=3600, stale-while-revalidate=86400` + `Vary: Cookie` to prevent FRED quota abuse while preserving per-user auth boundaries
- Market Stats page server-fetches the 30yr FRED rate (using server-only `FRED_API_KEY`) and passes it as a prefill prop to `MortgageCalculator` and `AffordabilityCheck` for instant-loaded live-rate defaults
- **Zillow API integration**: RapidAPI host `zillow-com-live-data-scraper-api.p.rapidapi.com` with base URL `https://zillow-com-live-data-scraper-api.p.rapidapi.com`; uses `/bycoordinates` endpoint with lat/lng from Google Places Autocomplete; **implements multi-signal fuzzy address matching** with weighted scoring: street number exact match (35% weight), token-based Jaccard similarity (25%), haversine geographic distance in miles (25%), Levenshtein character distance (15%); requires combined confidence score ≥0.45 for match; gracefully falls back when no street-number match exists; supports MLS ID lookup via `/bymlsid` endpoint; proxied through `/api/property-lookup` with consistent `{ok, data|error, errorType?}` envelope
- RapidAPI host configurable via `NEXT_PUBLIC_RAPIDAPI_ZILLOW_HOST` (host string is non-sensitive); Supabase schema selector uses `NEXT_PUBLIC_SUPABASE_SCHEMA` for client+server clients
- `/api/property-lookup` returns shape-specific payloads: `{ properties }` for POST (batch addresses with lat/lng), `{ property }` for GET (single address with lat/lng or `mlsid` query param); errors include `errorType: 'not_found' | 'connection' | 'auth' | 'quota' | 'validation' | 'unknown'` for granular client-side handling; route has 60s `maxDuration` for Vercel cold-start tolerance and logs sanitized timing (address prefix + elapsed ms) for diagnostics; error responses align with ZillowProperty shape for consistent client parsing
- `/api/property-lookup` auth is degraded-open: Supabase session check runs but logs+continues if missing in development (`NODE_ENV !== 'production'`), returns `401 { ok:false, error:'Unauthorized' }` in production; per-user sliding-window in-memory rate limit of 20 req/min returns `429 { ok:false, error:'Rate limit exceeded', errorType:'quota' }` with `Retry-After` header (note: in-memory limiter is per-instance and resets on cold start; revisit with Redis/Upstash if multi-instance accuracy required)
- **Zillow client (`lib/zillow.ts`)**: Uses RapidAPI host header `zillow-com-live-data-scraper-api.p.rapidapi.com` and base URL `https://zillow-com-live-data-scraper-api.p.rapidapi.com`; reads server-only `RAPIDAPI_KEY` from `process.env.RAPIDAPI_KEY` at request time; implements 30s timeouts, exponential backoff retry (3 attempts, 2s→4s→8s delays with jitter), coordinate validation (lat/lng within US bounds: 24.396308°N–49.384358°N, -125.0°W–-66.93457°W); `/bycoordinates` endpoint returns array of properties near lat/lng with **multi-signal fuzzy matching algorithm**: computes weighted confidence score from street number exact match (35%), token-based Jaccard similarity (25%), haversine geographic distance (25%), Levenshtein character distance (15%); requires combined confidence ≥0.45 for match; gracefully falls back when no street-number match exists; handles RapidAPI 404 (coordinates not found), 401/403 (auth), 429 (quota), network failures, and malformed responses with detailed logging (timestamps + address prefix + lat/lng + attempt number + error type + confidence score); `/bymlsid` endpoint for MLS ID lookups; exports `fetchPropertyByCoordinates` as primary named export with backwards-compatible `findBestMatch` alias
- Zod for form validation; sonner for toasts; framer-motion for staggered reveals and lift/scale interactions
- Client-side pipeline + comparisons + local market inputs state via React Context / localStorage; agent branding synced to Supabase with localStorage fallback
- Agent branding centralized in `AgentBrandingContext` with `isConfigured` (name+brokerage populated) and `hasProfile` (all required fields saved) flags; hydrates from Supabase on mount, saves via `/api/profile`, and falls back to localStorage; **location field persisted to both localStorage and Supabase agent_profiles table**; consumed by Sidebar live preview, ProfileForm validation, and ClientReport header
- **PipelineContext persistence**: `comparisons` array (stores full `ComparisonProperty[]` data per comparison, no lossy mapping) writes to localStorage on every state mutation (addComparison, updateComparisonNotes, updateComparisonClientName); `pipeline` array writes to localStorage on every mutation (addPipelineItem, updatePipelineStage, removePipelineItem); explicit `localStorage.setItem` calls in all mutator functions ensure immediate persistence
- PipelineContext tracks extended entries (price, clientName, notes, stageEnteredAt) and auto-stamps `stageEnteredAt` on stage transitions for days-in-stage tracking
- PipelineContext exposes `pipeline`, `updatePipelineStage`, `addPipelineItem`, `removePipelineItem`, `addComparison(properties, label?)` with auto-computed winner, plus `getComparisonById`, `updateComparisonNotes`, `updateComparisonClientName` for report editing
- `addComparison` is invoked with positional `(properties: ComparisonProperty[], label?: string)` args (not an object literal) — strict TS enforced in Vercel builds
- Saved comparisons persist `reportNotes` (per-property) and `clientName` for reuse in Client Report
- Local market inputs (median price, DOM, inventory, YoY, mortgage rate) persisted to localStorage with edit/save toggle; shape extracted as reusable `LocalMarketInputsData` type; **LocalMarketInputs reads `branding.location` from AgentBrandingContext to display dynamic location label** (e.g., "Median Days on Market in {location}") instead of hardcoded region references
- Mortgage math helpers (`calcMonthlyPayment`, `maxHomePriceForIncome`) live in `lib/utils` and assume 28% DTI for affordability
- Kanban drag-and-drop uses native HTML5 DnD (no external lib) for lightweight stage transitions with scale/shadow lift states
- Honeypot pattern for spam protection on quick-add forms
- Prefer `type` aliases over empty `interface` extensions to satisfy strict lint
- `/client-report` opts out of static prerender (`export const dynamic = 'force-dynamic'` + `revalidate = 0`); the `useSearchParams`-consuming inner client component is wrapped in a `Suspense` boundary to satisfy Next 14 CSR-bailout prerender rules on Vercel
- Profile page (`/profile`) server-fetches agent data via Supabase and renders `ProfileForm` with Supabase sync via `/api/profile`; named function declaration pattern for default export satisfies static analysis
- All layout and dashboard components use explicit `export default` statements (not inline default exports) for consistent module resolution; named exports removed to prevent import ambiguity
- Dashboard and all child components constrained with `overflow-x-hidden`, `max-w-full`, and `min-w-0` guards to prevent horizontal overflow; table components scroll horizontally within their containers
- `Input` component is a named export from `components/ui/Input.tsx` (not default export) to maintain consistent import patterns across the codebase
- **FRED rate labeling**: Dashboard `StatsGrid` displays national mortgage rates from FRED API with accurate '30-Year Mortgage Rate' label (not region-specific) since FRED MORTGAGE30US series provides US national averages
