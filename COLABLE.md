# Real Estate Agent Tool
Stack: nextjs-supabase-vercel-stripe
Created: 2026-05-16

## Decisions
- Next.js 14.2.33 (App Router) with strict TypeScript and `@/*` path alias — pinned to published patched release clearing the security deprecation advisory (14.2.37 was non-existent and caused ETARGET install failures)
- `next.config.js` enforces type-safety and lint correctness at build time (no `typescript.ignoreBuildErrors`, no `eslint.ignoreDuringBuilds`) so Vercel deploys fail fast on regressions
- Tailwind with AgentDesk semantic tokens (navy sidebar, steel-blue primary, Inter Tight display + Inter body)
- Design tokens stored as HSL triplets in `globals.css` to pair with `hsl(var(--token))` Tailwind wrappers
- Print stylesheet in `globals.css` hides app chrome, forces light tokens, and exposes page-break utilities; adds `.no-print` and report-specific screen + print styles (A4 framing, page-break-inside avoid, display font for printed header/footer)
- Supabase shared-schema client (browser + server) for cross-app data access
- FRED API as live source for mortgage rates (MORTGAGE30US + MORTGAGE15US), proxied via cached Next route with 12-week history per series
- All third-party API keys are server-only — `FRED_API_KEY` and `RAPIDAPI_KEY` are never `NEXT_PUBLIC_*` and are read only at request time on the server (API routes + server-side libs + server components); prevents inlining into client bundles
- `/api/mortgage-rate` returns `{ rate30yr: RateSeries, rate15yr: RateSeries }` with current value, week-over-week delta, and history points; `StatsGrid` is backward-compatible with this shape (legacy-shape fallback typing includes `currentDate`)
- `/api/mortgage-rate` is auth-gated via Supabase session (401 on missing session), per-user sliding-window in-memory rate limit of 30 req/min (429 with `Retry-After` header), and edge-cached with `Cache-Control: s-maxage=3600, stale-while-revalidate=86400` + `Vary: Cookie` to prevent FRED quota abuse while preserving per-user auth boundaries
- Market Stats page server-fetches the 30yr FRED rate (using server-only `FRED_API_KEY`) and passes it as a prefill prop to `MortgageCalculator` and `AffordabilityCheck` for instant-loaded live-rate defaults
- Zillow data via RapidAPI host `zillow-com-live-data-scraper-api.p.rapidapi.com` (switched from prior host); supports address lookup and MLS ID lookup (`/bymlsid`); proxied through `/api/property-lookup` with consistent `{ok, data|error, errorType?}` envelope
- RapidAPI host configurable via `NEXT_PUBLIC_RAPIDAPI_ZILLOW_HOST` (host string is non-sensitive); Supabase schema selector uses `NEXT_PUBLIC_SUPABASE_SCHEMA` for client+server clients
- `/api/property-lookup` returns shape-specific payloads: `{ properties }` for POST (batch addresses), `{ property }` for GET (single address or `mlsid` query param); errors include `errorType: 'not_found' | 'connection' | 'auth' | 'quota' | 'validation' | 'unknown'` for granular client-side handling; route has 60s `maxDuration` for Vercel cold-start tolerance and logs sanitized timing (address prefix + elapsed ms) for diagnostics
- `/api/property-lookup` auth is degraded-open: Supabase session check runs but logs+continues if missing in development (`NODE_ENV !== 'production'`), returns `401 { ok:false, error:'Unauthorized' }` in production; per-user sliding-window in-memory rate limit of 20 req/min returns `429 { ok:false, error:'Rate limit exceeded', errorType:'quota' }` with `Retry-After` header (note: in-memory limiter is per-instance and resets on cold start; revisit with Redis/Upstash if multi-instance accuracy required)
- Zillow client (`lib/zillow.ts`) implements 30s timeouts, exponential backoff retry (3 attempts, 2s→4s→8s delays with jitter), address validation (rejects < 10 chars, missing state/ZIP patterns), and granular error classification; handles RapidAPI 404 (address not found), 401/403 (auth), 429 (quota), network failures, and malformed responses with detailed logging (timestamps + address prefix + attempt number + error type)
- Zod for form validation; sonner for toasts; framer-motion for UI polish
- Client-side pipeline + comparisons + local market inputs + agent branding state via React Context / localStorage (no auth yet for app state, but property-lookup + mortgage-rate APIs now auth-gated in prod, degraded-open in dev)
- Agent branding centralized in `AgentBrandingContext` with `isConfigured` (name+brokerage populated) and `hasProfile` (all required fields saved) flags; consumed by Sidebar live preview, ProfileForm validation, and ClientReport header
- PipelineContext tracks extended entries (price, clientName, notes, stageEnteredAt) and auto-stamps `stageEnteredAt` on stage transitions for days-in-stage tracking
- PipelineContext exposes `pipeline`, `updatePipelineStage`, `addPipelineItem`, `removePipelineItem`, `addComparison(properties, label?)` with auto-computed winner, plus `getComparisonById`, `updateComparisonNotes`, `updateComparisonClientName` for report editing
- `addComparison` is invoked with positional `(properties: ComparisonProperty[], label?: string)` args (not an object literal) — strict TS enforced in Vercel builds
- Saved comparisons persist `reportNotes` (per-property) and `clientName` for reuse in Client Report
- Local market inputs (median price, DOM, inventory, YoY, mortgage rate) persisted to localStorage with edit/save toggle; shape extracted as reusable `LocalMarketInputsData` type
- Mortgage math helpers (`calcMonthlyPayment`, `maxHomePriceForIncome`) live in `lib/utils` and assume 28% DTI for affordability
- Kanban drag-and-drop uses native HTML5 DnD (no external lib) for lightweight stage transitions
- Honeypot pattern for spam protection on quick-add forms
- Prefer `type` aliases over empty `interface` extensions to satisfy strict lint
- `/client-report` opts out of static prerender (`export const dynamic = 'force-dynamic'` + `revalidate = 0`); the `useSearchParams`-consuming inner client component is wrapped in a `Suspense` boundary to satisfy Next 14 CSR-bailout prerender rules on Vercel
- Profile page (`/profile`) reuses `AgentBrandingForm` from client-report folder (single source of truth for branding UI); named function declaration pattern for default export satisfies static analysis
- Component exports use default exports for consistency with Next.js App Router imports; enables tree-shaking and satisfies strict linting

## Components
- Layout: `Sidebar` (collapsible dark-navy nav with live agent logo/initials preview + Settings section showing unsaved-profile nudge if `isConfigured` but not `hasProfile`), `TopBar` (sticky, page title + date), `AppShell`
- Pages: Dashboard (`/`), Property Comparator (2–5 addresses or MLS IDs with toggle; elapsed-time loading indicator + slow-cold-start hint after 20s; parallel lookup with 30s timeout + 3-attempt exponential backoff (2s→4s→8s); address/MLS validation with inline hints; per-card exponential-backoff Retry button; bulk Retry-failed action for multi-card errors; calls `addComparison(properties, label?)` with positional args; save/clear/print), Pipeline (kanban with summary bar + inline add form + DnD across stages), Market Stats (server-fetched live 30yr rate prefill via server-only `FRED_API_KEY` + local inputs + mortgage calc + affordability), Profile (`/profile`, renders `AgentBrandingForm` from client-report folder for consistent branding UI), Client Report (`/client-report`, force-dynamic + Suspense-wrapped inner component reading `?comparisonId=`, saved-comparison dropdown + agent branding + printable preview), Email Report (stub)
- Dashboard widgets: `StatsGrid` (live FRED 30yr rate via new API shape with legacy fallback typing incl. `currentDate`, Florida labeling), `StatCard`, `RecentComparisons`, `QuickAddToPipeline`
- Comparator: `AddressInputs` (dynamic 2–5 with MLS-ID toggle + client-side validation + inline format hints: 10-char min, state/ZIP required for addresses; numeric-only for MLS), `PropertySkeletonCard`, `PropertyCard` (default export; Best/Highest Value badges), `PropertyErrorCard` (default export; granular errorType-based UI with tailored troubleshooting: yellow informational for not_found with "verify address/MLS ID" + Zillow link, red actionable for connection/auth/quota with specific remediation steps; exponential-backoff Retry button using last-known search mode and attempt count state), `ComparisonTable` (scannable metrics, Best Value & Highest Value highlights, red >60 DOM), `ClientReport` (printable branded modal with per-property pages)
- Pipeline: `AddPropertyForm` (inline address/price/client/stage/notes), `PipelineSummaryBar` (total value, per-stage counts, longest-sitting deal), `PipelineCard` (draggable, days-in-stage badge, expandable notes, delete), `KanbanBoard` (4 stage columns with HTML5 drag-and-drop)
- Market Stats: `Sparkline` (token-styled inline SVG), `RateDisplay` (current rate, WoW delta, sparkline via correct `data` prop), `LiveRatesSection` (fetches /api/mortgage-rate with skeleton+retry, renders 30yr/15yr cards + FRED source caption), `LocalMarketInputs` (zod-validated, localStorage-persisted, edit/save toggle with 5 stat cards), `MortgageCalculator` (real-time P&I, live-rate prefill prop, 15/30yr term), `AffordabilityCheck` (28% DTI max-price calc with live-rate prefill prop + assumptions panel)
- Client Report: `ComparisonSelector` (dropdown of saved comparisons), `AgentBrandingForm` (shared with /profile; persisted agent identity + logo + success toast + 'Saved' indicator; uses named function declaration default export), `ReportPreview` (branded printable layout with header/footer pulling from AgentBrandingContext), `PropertySummaryBlock` (photo, address, Price|Beds|Baths|Sqft|$/sqft, Best/Highest Value badges, editable per-property notes), `ReportActions` (Print/Save-as-PDF + Copy shareable link with sonner toast, hidden during print)
- UI primitives: `Button`, `Input`, `Select`, `Card` (+ subcomponents), `Skeleton`, `EmptyState`
- State: `AgentBrandingContext` (centralized branding state with `isConfigured` and `hasProfile` flags, localStorage-backed; consumed by Sidebar, Profile, ClientReport), `PipelineContext` (extended pipeline entries + saved comparisons with reportNotes/clientName/winner, localStorage-backed; exposes getComparisonById/updateComparisonNotes/updateComparisonClientName)
- API: `/api/mortgage-rate` (cached FRED proxy using server-only `FRED_API_KEY`, returns 30yr+15yr series with 12-week history + WoW deltas; Supabase session auth-gated — 401 on missing session; per-user sliding-window rate limit 30 req/min — 429 with `Retry-After`; edge-cached `s-maxage=3600, stale-while-revalidate=86400` + `Vary: Cookie`), `/api/property-lookup` (Zillow via `zillow-com-live-data-scraper-api` RapidAPI host using server-only `RAPIDAPI_KEY`; degraded-open auth — logs+continues if no session in dev, 401 in prod; per-user sliding-window rate limit 20 req/min — 429 with `Retry-After` + `errorType:'quota'`; 60s maxDuration for cold-start tolerance with sanitized timing logs; POST→`{ properties }` batch address lookups, GET→`{ property }` for `?address=` or `?mlsid=` single lookup; returns `errorType` for granular client handling)
- Lib: `lib/fred.ts` (server-only — reads `FRED_API_KEY` at request time; multi-series helper), `lib/zillow.ts` (server-only — reads `RAPIDAPI_KEY` + configurable host via `NEXT_PUBLIC_RAPIDAPI_ZILLOW_HOST`; exports `fetchPropertyByAddress`, `fetchPropertyByMlsId` (/bymlsid endpoint), and parallel-address helper; implements 30s timeout, 3-attempt exponential backoff with jitter (2s→4s→8s), address validation (min 10 chars, state/ZIP pattern), granular error classification with detailed diagnostic logging: timestamps + address prefix + attempt number + error type), `lib/utils.ts` (cn, currency/date/number/percent formatters, `daysBetween`, `calcMonthlyPayment`, `maxHomePriceForIncome`), `lib/supabase/{client,server}.ts` (both read `NEXT_PUBLIC_SUPABASE_SCHEMA`; server client used by property-lookup + mortgage-rate routes for session-based auth check)
- Types: shared `types/index.ts` (incl. `ComparisonProperty`, `ComparisonResult` with reportNotes+clientName, extended `PipelineEntry`, `RateSeries`, `LocalMarketInputs`, `LocalMarketInputsData`, `MortgageCalc*`, `AgentBranding`)
- Config: Tailwind tokens, PostCSS, `next.config.js` (strict builds — no TS/ESLint bypass flags), `package.json` (next pinned to 14.2.33 — valid published security patch), `.env.example` (Supabase shared-schema via `NEXT_PUBLIC_SUPABASE_SCHEMA` + server-only `FRED_API_KEY` used by both /api/mortgage-rate and Market Stats server page + server-only `RAPIDAPI_KEY` + non-sensitive `NEXT_PUBLIC_RAPIDAPI_ZILLOW_HOST` for Zillow live-data scraper host; documents comprehensive Zillow/RapidAPI troubleshooting: 401/403→verify key+host match RapidAPI dashboard, 404→check address format or use MLS-ID toggle, 429→upgrade RapidAPI plan or wait for quota reset, timeout→expect Vercel cold starts 10–30s first request or network issues, malformed→contact RapidAPI support for schema changes), README (documents server-only key conventions + expanded Property Comparator troubleshooting section: Vercel cold-start expectations with 60s route timeout, exponential-backoff retry strategy, per-card vs bulk retry UX, address-vs-MLS-ID validation rules, and actionable steps for not-found vs connection/auth/quota errors mapped to yellow/red card states)
